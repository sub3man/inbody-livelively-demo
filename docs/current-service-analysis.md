# 현재 서비스 정밀 분석

> 작성일 2026-06-13 · 대상 커밋 기준 브랜치 `oss-enhancement/2026-06-13`

## 0. 한 줄 요약

이 저장소는 **풀스택 SaaS가 아니라, 단일 정적 HTML 파일로 구성된 "InBody × 리브라이블리" 파트너십 제안용 인터랙티브 데모(원페이저 피치)** 입니다. 따라서 일반적인 서비스 분석 항목 중 다수(백엔드/DB/ORM/인증/API/배포 파이프라인 등)는 **물리적으로 존재하지 않습니다.** 본 문서는 사실을 지어내지 않고, 존재하는 것만 분석하고 없는 것은 "해당 없음(N/A)"으로 명시합니다.

## 1. 서비스 요약

- **목적**: InBody 액셀러레이터(InBodyLIKE)·투자/제휴 대상에게 보여줄 협업 시나리오 데모.
- **서사**: 측정 → AI 위험분류 → 방문운동 → 생활습관 코칭 → 12주 재측정·리포트의 "폐쇄 루프".
- **형태**: 탭 5개(파트너십 개요 / CareFlow OS / NoriCare / 성과 리포트 / 협업 제안)를 가진 클라이언트 사이드 SPA. 라우팅은 URL 해시(`#home`, `#cf`, …)로 처리.
- **인터랙티브 요소**: 위험도 분류 시뮬레이터(슬라이더), 임팩트 시뮬레이터(슬라이더), Chart.js 차트 3종, 가이드 투어 버튼/방향키 내비게이션, 참여자 목록 필터.

## 2. 현재 아키텍처

| 레이어 | 실제 구현 | 비고 |
|---|---|---|
| 기술 스택 | 순수 HTML + CSS + Vanilla JS (단일 `index.html`, ~1,750줄) | 프레임워크 없음 |
| 프론트엔드 구조 | 인라인 `<style>` + 인라인 `<script>` 1개. 탭 = `.view` div, `go(id)`로 토글 | 컴포넌트화/모듈화 없음 |
| 외부 의존성 | Pretendard(웹폰트, jsDelivr CDN), Chart.js 4.4.0(cloudflare CDN) | 둘 다 CDN 직접 로드 |
| 상태 관리 | 전역 함수 + `window._pChart/_mChart/_aChart` 플래그, `location.hash` | 프레임워크 상태 라이브러리 없음 |
| 디자인 시스템 | CSS 커스텀 프로퍼티(`:root`) 토큰(색/반경/모션) + 유틸 클래스(`.g2`,`.mb16` 등) | 일관성 양호 |

| DB / ORM | **해당 없음** | 영속 데이터 없음 |
| 인증 / 권한 | **해당 없음** | 로그인 없음 |
| 테스트 | **해당 없음** | 테스트 프레임워크·파일 없음 |
| 빌드 / 번들러 | **해당 없음** | `package.json`/번들러 없음, 파일 그대로 서빙 |
| 배포 | 정적 호스팅 추정(GitHub Pages 등). CI 워크플로 없음 | `total_count:0` (체크 없음) |

## 3. 주요 기능 목록

1. 5탭 SPA 내비게이션(클릭 / 해시 / 좌우 방향키 / 플로팅 투어 버튼).
2. 위험도 분류 시뮬레이터 — SMI·악력·보행속도 슬라이더 → 점수화 → 고/중/관찰 분류 + 권장 개입 텍스트.
3. 임팩트 시뮬레이터 — 자치구·대상자·측정주기 슬라이더 → 연간 측정/데이터포인트/거점 수 카운트업.
4. CareFlow OS 대시보드 목업 — KPI strip, 오늘 방문 일정, 참여자 표(위험도 필터), 기능개선 막대차트, 위험도 분포 바.
5. NoriCare 모바일 앱 목업 — 폰 3대(홈/리포트/프로그램), 12주 성과 라인차트(지표 전환), 코치 카드.
6. 성과 리포트 — Baseline→W12 표, 개선율 가로 막대차트, 타임라인, 로드맵, 공동 브랜드 리포트 미리보기.
7. 협업 제안 — 역할 카드, 임팩트 시뮬레이터, 4개월 일정, 연락처.

## 4. 강점

- **서사 완성도**가 높고 수치 정합성이 좋음(예: SMI +17.3% = (6.1−5.2)/5.2, 9,600 = 12×200×4 등 계산이 모두 일치).
- **디자인 토큰 일관성** — 색/반경/모션을 CSS 변수로 통일, 반응형 처리(960/520px)와 한글 `word-break:keep-all` 적용.
- **의존성 최소** — 외부 JS는 Chart.js 하나뿐. 빌드 없이 즉시 열람 가능.
- **인터랙션이 실제 동작**(슬라이더·필터·차트 전환·투어)하여 "살아있는" 데모 인상.
- 이미 직전 작업에서 **SEO(OG/Twitter 카드)·이미지 접근성(alt)·지연 로딩**을 보강함.

## 5. 약점 / 기술 부채

1. **죽은 버튼** — "결과보고서 내보내기 / PDF 내보내기 / 보호자 리포트 / 내보내기 / B2G 제안 패키지"가 클릭해도 아무 동작이 없었음(피치에서 신뢰 저하 요인). → 본 작업에서 인쇄/PDF 4종 연결로 일부 해소.
2. **CDN 의존** — 폰트·Chart.js가 외부 CDN. 현장 발표 중 네트워크 단절 시 폰트 깨짐·차트 미표시 리스크.
3. **렌더 블로킹** — Chart.js가 `<head>`에서 동기 로드. 단, 현재 init 코드가 인라인 스크립트에서 즉시 `new Chart()`를 호출하므로 단순 `defer`는 딥링크(#cf 등)에서 깨질 수 있음(주의 필요).
4. **키보드 접근성** — 상단 탭(`.ntab`)과 참여자 표 행(`<tr onclick>`)이 `div`/`tr`+onclick이라 키보드 포커스·Enter 미동작. `role`/`tabindex`/`button`화 필요. (`aria-*` 사용 0건)
5. **콘텐츠 하드코딩 날짜** — "리포트 생성 2026.06.12", "PoC D-38" 등 시간 경과 시 어긋남.
6. **모션 과다** — 펄스/카운트업 다수, `prefers-reduced-motion` 미대응.
7. **단일 거대 파일** — 1,750줄에 스타일·마크업·로직 혼재. 데모로선 무방하나 협업·확장 시 부담.

## 6. 보안 / 라이선스 관점

- 입력은 슬라이더(number)뿐이고 서버 전송이 없어 **공격면이 사실상 없음**(저장 XSS/주입 불가). `innerHTML`로 렌더하는 곳은 모두 하드코딩 데이터 기반이라 현재는 안전.
- 비밀값/토큰/`.env` **없음**(정적 데모). 노출 위험 없음.
- 외부 자산 라이선스: Chart.js(MIT), Pretendard(SIL OFL 1.1) — 상업적 사용 가능. 상세는 `open-source-attribution.md`.

## 7. 오픈소스 참고가 특히 유용한 영역

1. **인쇄/PDF 산출물** — 제안서는 결국 PDF로 공유됨. print-CSS / paged.js / html2pdf 패턴.
2. **프레젠테이션 모드** — reveal.js·impress.js의 슬라이드 전환·발표자 UX.
3. **디자인 토큰 체계** — Open Props식 토큰 명명/구조.
4. **정적 사이트 접근성** — a11y 패턴(포커스 관리, ARIA, reduced-motion).

## 8. 빠르게 구현 가능한 개선안 (낮은 리스크)

- ✅ **(이번 구현)** 죽은 export 버튼 → 브라우저 인쇄/PDF 연결 + 인쇄 전용 CSS. 의존성 0, 오프라인 동작.
- 키보드 접근성: 탭/표 행 `role="tab"|"button"` + `tabindex` + Enter 핸들러.
- `prefers-reduced-motion` 미디어쿼리로 애니메이션 차단.
- CDN 자산 로컬 번들링(오프라인 발표 안정성).

## 9. 장기적으로 혁신적인 개선안

- 발표자 모드(전체화면 슬라이드 전환) — reveal.js 패턴 참고.
- 시뮬레이터 값 → URL 파라미터 직렬화로 "내 시나리오 공유 링크" 생성.
- 데이터 레이어 분리(JSON) → 자치구별/대상자별 데이터 교체로 멀티 데모.
